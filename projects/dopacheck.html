DopaCheck

배달 한 번, 스크롤 한 시간 — 내 도파민 소비를 숫자로 마주하는 서비스. 영수증·사용시간을 올리면 AI가 일상 활동·금전 가치로 환산합니다.

2026.06.10 – 06.17 (7일) 6인 팀 담당: 프론트엔드·관리자·배포
시연 영상 ↗ GitHub ↗ Deck ↗

개요

배달 음식·디지털 소비를 대체 활동(책·강의·운동 등)의 금전 가치로 환산해 "도파민 점수"로 보여주는 7일짜리 해커톤형 프로젝트입니다. AI 심화 과정 6인 팀이 진행했고, Claude API로 영수증 OCR·칼로리 추론·챌린지 추천까지 처리합니다.

담당 역할

  • 배포 설정 — Procfile·헬스체크 구성으로 Cloudtype 자동 배포 파이프라인 셋업
  • 프론트엔드 — 헤더, 아바타 드롭다운, 파비콘 등 전 화면 공통 UI 구현
  • 관리자 페이지 — 챌린지 관리, AI 추천 결과 운영, 유저 상세 조회 화면
  • 시간 분석 페이지 — 앱별 사용 시간을 대체 활동·시급 기준 기회비용으로 환산해 보여주는 `/time` 화면
  • Stitch UI 제작 — Google Stitch로 디자인 목업을 제작해 팀 전체 UI 톤을 통일

핵심 기능

🍗 배달 분석
영수증 사진 업로드 → AI(OCR) 자동 추출 → 지출·칼로리를 일상 활동으로 환산
⏰ 시간 분석
앱별 사용 시간 입력 → 대체 활동·시급 기준 기회비용 환산
🔥 도파민 점수
0~100 점수 산출, 전체 평균 대비 / 상위 N% 랭킹
🏆 AI 챌린지
히스토리 기반 맞춤 챌린지 추천, 달성 시 점수 개선

막힌 지점과 해결

Supabase → MariaDB 전환
상황RLS·Supabase SDK 기반 코드가 자체 호스팅으로 전환한 신규 DB에서 전면 호환 불가 — 비용·제어권 확보를 위한 결정
해결RLS 대신 앱 레벨 WHERE user_id=%s 필터 + (provider, provider_id) upsert로 대체, 팀에 rebase 가이드 배포
교훈DB 전환은 쿼리 문법뿐 아니라 보안 모델(격리 방식)까지 함께 재설계해야 함
챌린지 참여 버튼 전부 실패 (HTTP 400)
상황스키마는 CHAR(36) UUID인데 코드가 int(challenge_id)로 변환을 시도해 전체 요청이 400
해결UUID 문자열을 그대로 사용하도록 수정하고 INSERT 검증 테스트 추가
교훈스키마 변경 시 운영 DB의 실제 상태까지 대조해야 함
동시 요청 시 커넥션 풀 고갈
상황PooledDB의 blocking=True 기본값 때문에 DB 커넥션 대기가 무한 행으로 이어짐
해결blocking=False + 바운드 타임아웃 적용, 고갈 시 503으로 graceful하게 응답
교훈자원 경합 지점은 타임아웃·degradation 경로를 반드시 함께 설계해야 함

배운 점

깃·DB·프론트·서버를 담당자별로 나눠 분담하니 이전보다 협업이 한결 원활했습니다. PRD 작성 등에서 AI 활용 역량이 한 단계 향상됨을 느꼈고, Supabase→MariaDB 전환과 커넥션 풀·UUID 정합성 트러블슈팅을 통해 실무형 디버깅·인프라 역량을 키웠습니다.
